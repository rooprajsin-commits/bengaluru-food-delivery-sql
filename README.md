# Bengaluru Food Delivery Analytics — an end-to-end PostgreSQL project

Cleaning, transforming and visualising 6,000+ messy food-delivery orders across 10 Bengaluru localities, **entirely in PostgreSQL**.

> The dataset is synthetic (generated by `data/generate_data.py`) but built to behave like real app data: duplicate events, mixed date formats, currency symbols in numbers, 36 spellings of 10 area names, impossible delivery times, and realistic business patterns (festive spikes, monsoon delays, cash-on-delivery cancellations).

---

## Pipeline

```
 CSV files ─► RAW (all TEXT) ─► audit ─► STAGING (clean, typed) ─► ANALYTICS (star schema) ─► views ─► charts
             01_load_raw     02_audit     03_clean                  04_transform           05_views   06_visualize
                                              │
                                              └─► staging.rejected_orders (nothing is silently dropped)
```

| Layer | What happens | Key SQL techniques |
|---|---|---|
| **Extract** `01_load_raw.sql` | Load CSVs as-is, every column `TEXT` | `\copy`, schema separation |
| **Profile** `02_data_quality_audit.sql` | Measure every data problem before fixing | `FILTER`, regex `~`, CTEs |
| **Clean** `03_clean.sql` | Parse, standardise, de-duplicate, validate | PL/pgSQL functions, `regexp_replace`, `ROW_NUMBER()`, lookup table, rejected-rows log |
| **Transform** `04_transform.sql` | Build a star schema | `generate_series` date dim, `IDENTITY` keys, `GENERATED` columns, FKs, `CHECK`s, indexes, reconciliation test |
| **Model** `05_reporting_views.sql` | 9 business-ready views (BI tools can connect to these) | `LAG`, `NTILE`, `RANK`, `FIRST_VALUE`, `SUM() OVER`, cohort & RFM analysis |
| **Visualise** `06_visualize.sql` | 9 charts drawn inside psql | custom `bar()` / `shade()` functions, `string_agg`, heatmap via `CROSS JOIN` |

### Star schema

```
                 dim_date
                    │
 dim_customer ── fact_orders ── dim_restaurant
```
`fact_orders.net_revenue` and `is_late` are **generated columns** — the database computes them, so every report uses the same definition.

## Data cleaning results

| Problem found in raw data | Rows | Fix |
|---|---|---|
| Duplicate order events | 120 | Kept first copy with `ROW_NUMBER()` |
| Non-ISO timestamps (`29/10/2025 16:32`, `01-May-2025 12:20 PM`) | 1,778 | `parse_ts()` handles 6 formats |
| Amounts like `₹1,234.50`, `Rs. 980` | 1,549 | `parse_amount()` |
| 36 spellings of 10 areas (`HSR`, `H.S.R Layout`, `Kormangala`…) | — | normalised key + `area_mapping` table → 10 clean areas |
| 10 spellings of order status, 15 of payment method | — | `CASE` + pattern matching |
| Missing order value | 314 | Rejected & logged |
| Orders for a restaurant that doesn't exist | 53 | Rejected & logged |
| Negative / 999-minute delivery times | 74 | Set to `NULL`, flagged, order kept |
| Ratings of 0 or 6 | 149 | Set to `NULL`, flagged, order kept |

**6,120 raw rows → 5,633 clean orders**, every removed row accounted for.

## Key findings

1. **Late delivery destroys ratings.** Orders under 25 min average **4.13★**; orders over 45 min average **2.92★**, and 36% of them get 1–2 stars (vs 8%).
2. **Whitefield and Electronic City have a delivery problem.** ~20% of their orders arrive late vs ~1–3% in Indiranagar / Koramangala, and they have the lowest ratings in the city.
3. **Festive season drives the year.** October–November alone produce **27.6%** of annual revenue; October revenue jumped **75%** month-on-month.
4. **Monsoon slows everything.** Average delivery time rises from **31.7 → 37.8 min** in June–September.
5. **Cash on delivery is the cancellation risk.** COD cancels at **21%** vs ~7% for UPI, card and wallet.
6. **A small group carries the business.** "Champions" are **29.5% of customers but 74% of revenue** (RFM segmentation).
7. **Weekends and dinner matter most.** Weekends average 18.5 orders/day vs 14.2 on weekdays; 7–10 PM is 37% of all orders.

**Recommendations:** add riders / dark kitchens in Whitefield & E-City before the monsoon, nudge COD users toward UPI (or require pre-payment for repeat cancellers), staff up for Oct–Nov, and run a retention programme for "At Risk" and "Needs Attention" customers.

## How to run

**Requirements:** PostgreSQL 13+ (tested on 16). Python is *not* needed — the CSVs are included.

```bash
# from the project folder
createdb -U postgres food_delivery
psql -U postgres -d food_delivery -f run_all.sql
```

**Windows tips**
- If `psql` isn't recognised, use the full path: `"C:\Program Files\PostgreSQL\16\bin\psql.exe"`.
- For the chart characters to display, run `chcp 65001` first in Command Prompt.
- In **pgAdmin**, right-click the database → **PSQL Tool**, then run `\cd 'C:/path/to/project'` and `\i run_all.sql`. (The normal Query Tool doesn't understand `\copy` / `\i`.)

Run a single step any time, e.g. just the charts: `psql -d food_delivery -f sql/06_visualize.sql`.

**Connect a BI tool (optional):** point Power BI / Tableau / Metabase at the `analytics` schema and use the `v_*` views directly.
